# ADR 0033 – Clinical coding and statutory reporting (NMDS, NBRS)

Status: Accepted (0.20.0)

## Context
Spec 7.11 asks for a coder workbench in ICD-10-AM/ACHI/ACS with edit checks, and extracts to Health NZ: the National Minimum Dataset (NMDS) for hospital events and the National Booking Reporting System (NBRS) for outsourced electives, with pre-submission validation, a submission log and error resubmission. New Zealand codes in **ICD-10-AM/ACHI/ACS Twelfth Edition** (clinical coding system 16, from 1 July 2023); Australia moved to Thirteenth Edition on 1 July 2025 but NZ has not, so IHACPA advice published since then applies in NZ only after Health NZ reviews it. Private hospitals report to the NMDS with the "Private Hospitals Load File Format" (CSV). NBRS uses file specification document 4.5 (file version V04.0). The NZ Clinical Coding Conventions and NMDS Reporting Requirements (July 2023 v1.1) add NZ rules on top of the Australian Coding Standards.

## Decision
- **New module `reporting` ("Coding & statutory reporting", schema `coding`)**; permissions coding.code (workbench, Health NZ errors, NBRS entries), coding.submit (create/download/send files, acknowledgements), coding.manage (settings, code table, picklist, advice, registrations); new role **Clinical Coder**; System Administrator gets coding.manage. A new not-yet-built module "claims" (ACC/insurer claims, Xero, EFTPOS, NHI/HPI) takes over as the "coming later" entry.
- **The code table is imported, not shipped.** The classification is licensed: an administrator imports the clinical code table Health NZ supplies (CSV; columns found by name – system, code, type, description, sex flag, age range, never-assigned flag, end date). Codes are stored without punctuation (K635, 3209300) and shown formatted (K63.5, 32093-00). The coding system id and edition name are settings, so a new edition is an import plus two fields – not a rebuild (spec 7.11 "versioned extracts").
- **Queue:** every discharged or transferred eMR episode becomes a coded event (purchaser code from the booking's payment type through settings: self-funded/insurer 06, ACC A0, Health NZ 35; event end DR, or DA when transferred). NZ convention on ACS 0029: only one hospital reports a contracted event, preferably the public hospital – Health NZ funded events are marked "not reported by TDS" unless the setting says TDS reports them. Events past the reporting time (default 21 days) are flagged.
- **Edit checks** (`CodingChecks`, errors block "coded", warnings do not): one principal diagnosis; codes in the table, active and of the right type for A/B/O/E/M; ACS 0049 never-assign codes; sex and age edits; procedure/accident dates within the event; description required, ≤ 50 characters; ACS 0031 – anaesthesia code expected when the booking had general/sedation/regional anaesthesia, and 92513 infiltration not assigned; ACS 2001 – injuries need an external cause; NZ convention – Z03.6 needs substance, place (Y92) and activity (U50–U73); NZ NMDS requirement – free text, not the classification title, for complications, injuries and external causes, and mesh brand/size/type; NZ convention on gender reaffirming surgery (Z41.89 principal, F64 additional, from 1 July 2025). The NMDS sex field takes F/M – indeterminate/unknown is a warning to check.
- **Advice library:** IHACPA rules/FAQs and NZ conventions with their **NZ review status** (applies to NZ Twelfth Edition yes/no, reviewed date) and code prefixes; only advice that applies is shown on the workbench. Summaries are written in TDS's words with a link to the published text. Starter items cover the NZ conventions and ACS 0031; the Thirteenth Edition rule on ophthalmic blocks (Q3725) is loaded as not applicable until reviewed.
- **NMDS file:** `NmdsService` builds the load file – CSV with the header row, character fields in double quotes, ASCII (macrons removed), name split into first/second/third, address lines, two-digit ethnic codes from the HISO level-4 codes (description only when the code is not in the load file table, e.g. 61), repeating groups DIAGTYPE/DESC/DIAGCODE/CODESYS/OPDATE padded to the longest event. Named AAA0YYMM.CSV. Each event keeps a stable 14-character record id so a corrected resubmission replaces it. Patient problems (no address line 1, bad NHI) and edit-check errors keep an event out and are listed. Submission log: created → sent → accepted / returned with errors; Health NZ errors are recorded on the event, which returns to the coder and goes in the next file (marked as a resubmission).
- **NBRS:** entries (local booking id ≤ 14, facility, booking source, referral/first assessment/CPAC dates, CPAC score and tool, purchaser, health specialty, planned procedure code, domicile, professional group and clinical responsibility code from the clinician's Medical Council registration, assessor, staged/planned flag) drafted from Health NZ funded waitlist entries; events book 01, certainty 02, defer 05, rebook 06, exit 20 (treated category 11 needs the client system identifier = the NMDS record id), change C, delete D, erase E. `NbrsService.Validate` applies the error conditions checkable locally (E1, E4, E6–E8, E12–E13, E16–E18, E21, E24–E27, E37–E48). Batches: BH header + one BE record per event (35 fields in the specification's order, char fields unquoted, CRLF), named AAA00001.NBR with gap-free sequence numbers kept separately for CMPL and PROD. The acknowledgement (.NBK: AH, AC/RJ with ER/WN) is loaded back onto each event by line number.
- Files leave through the secure export (AES-256 ZIP by default) and every download is audited. Patient merge moves coded events and NBRS entries.

## Consequences
- The ICD/ACHI content and Health NZ code tables (purchaser, specialty, facility, domicile, CPAC tools) must be obtained from Health NZ; the demo uses a small sample with BrightPAS's own descriptions.
- NBRS is usually reported by the District for its own bookings; TDS uses it only where a contract says so. The checks are local – Health NZ's acknowledgement remains the authority.
- Not yet: AR-DRG/WIES grouping, ACC and insurer claims (planned "claims" module), HQSC/Medsafe registry submissions (incident module records notifications), NBSP extract layout (awaiting Health NZ), NNPAC.
