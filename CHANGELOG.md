# Changelog

## 0.28.0 – 2026-11-25 – **Bookings from specialists' rooms**
- **Bookings from rooms module (ADR 0041, guide H35)** – licence "ebookings"; permissions Send booking requests (Surgeon, PA, Specialist portal) and Manage booking requests (Reception / Booking); "Bookings from rooms" under Before surgery.
  - **Portal:** specialists and PAs send a booking request from the specialist portal – patient, procedure (from TDS's list or typed), side, anaesthetic, minutes, urgency, funding and approval/claim number, dates wanted and days to avoid, clinical notes, pre-op details (weight, height, BMI, ASA, diabetes, sleep apnoea, blood thinners, allergies, responsible adult, consent) and up to 8 letters/scans. They see each request's status, answer TDS's questions, add files, withdraw, and see the waitlist status and booked date once accepted. A possible duplicate must be confirmed.
  - **Booking office:** list by To do / Waiting for the rooms / Accepted / Declined; "points to check" for day-surgery suitability and missing paperwork; ask the rooms a question; match the patient (same NHI or same date of birth and name – a different NHI is refused) or register them from the request; **accept onto the waitlist** (referral and waitlist entry created, the rooms' dates and pre-op details in the waitlist notes, files filed in the patient record) or decline with a reason. Requests received by phone or fax can be entered here. My list shows requests to check.
  - **Files from practice systems:** BrightPAS booking JSON (example file to give practices) or HL7 v2 REF^I12 referrals – upload, or a watched share/USB folder checked every two minutes; the same rooms reference is never imported twice.
  - Optional email to the rooms contact when TDS asks, accepts or declines (no patient details; uses the Reminders email settings).
  - Set-up wizard, demo data (requests at every stage, an HL7 import), patient merge, self-test entries, reporting foreign keys.
- IIS upload limit raised from 50 MB to 130 MB (web.config and Setup) so NZ Formulary PDFs up to 120 MB import on IIS; other pages keep the app's normal 30 MB limit.
- Demo data: the medicines step picks the patient's original penicillin allergy (a second, date-dependent alert from the questionnaire made loading fail on some days).
- Test robot: **Bookings from rooms** steps (PA answers a question, sends a request with a letter; booking office registers and accepts; HL7 import; PA can't see the office list or another specialist's request).

## 0.27.0 – 2026-11-25 – **Medicines and medicine safety: dose limits, allergy groups and interactions**
- **Medicines module (ADR 0040, guide H34)** – licence "medicines"; permissions View / Medicines list / Rules / Approve rules; Medicines under Day of surgery.
  - **Medicines list:** starter list of about 45 day-surgery medicines with strengths, TDS's own entries (ingredients, strength per tablet/vial or per mL, usual route, pack barcodes), other names for ingredients (Panadol, lignocaine, Augmentin…). **Import** the free NZULM monthly file (or TDS's own list) with a column layout chosen once and saved; medicines missing from a full file are made inactive.
  - **Rules:** versioned and clinician-approved like the triage rules – dose limits (per dose, per 24 hours across every product, per kg, hours apart, by route and age), allergy groups (penicillins, cephalosporins, NSAIDs, opioids…), cross-reactions (penicillin → cephalosporin) and interactions (QT, serotonin, sedation, bleeding, Parkinson's, sugammadex and contraception…). Example rules ship as a draft, **not clinically approved**.
  - **Checks when charting:** the clinical record checks each medicine as it is typed – allergies (by link, name or other name), dose limits with the 24-hour total from every episode (SaferSleep filings included), weight from triage or the questionnaire, too soon / possible double dose, interactions with medicines already given and the patient's own medicines from the questionnaire. Anything that couldn't be checked is said. **Advise** (default: shown, never blocked) or **Enforce** (a stop needs a reason). Every check is kept with its findings and any reason; the medicines list shows "checked – clear", "warnings" or "given despite a stop".
  - **Allergy links:** link a patient's allergy alert to an ingredient or group on the patient page, so checks don't depend on the wording.
  - Report (stops and overrides), set-up wizard, demo data (rules approved for demonstration only, a linked penicillin allergy, checks), patient merge, self-test entries, barcode lookup ready for barcode medicine administration.
- **NZ Formulary import (NZF and NZFC):** import the monthly PDFs (upload, a watched share/USB folder, or automatic download on the first working day of the month, default address nzf.org.nz/home/downloadpdf). BrightPAS reads every drug monograph – indications, contra-indications, cautions, renal and hepatic impairment, pregnancy, breast-feeding, adverse effects, patient advice, dosing by indication/route/age/weight, preparations – and adds the drug names and synonyms to the medicines list. NZF real release 173: 1,464 monographs and 4,698 dosing lines in 23 s; NZFC 972 monographs. Shown under Medicines › NZ Formulary and linked from the medicine check; where TDS has no dose limit the check shows the NZF dosing (information only); **Suggest from NZF** fills a draft rule set with limits for the TDS list (highest per route and age/weight band) for clinicians to tick and approve. Dose limits can now have a body-weight band.
- NZULM carries no dosing or interaction information (clinical decision support is in the licensed NZ Formulary), so the rules are TDS's own until a licensed source is added.
- SaferSleep: no change needed – HL7 results, file import and a watched folder have been in place since 0.17/0.18.
- Audit log: writers now queue on one database lock, so two staff saving at the same moment no longer deadlock (an occasional failed page load under the robot's load).
- Test robot: **Medicines & medicine safety** steps (live check, enforce with/without a reason, patient panel, barcode, nurse can't approve).

- Triage: a link to a triage that has since been re-run (new answers arrived) opens the current one instead of a read-only old record.
- Demo data: completed EMR records are written as at 5 pm so loading the demo late in the morning no longer fails ("time cannot be in the future").
- Demo: funders with provider numbers, approvals, claims at every stage, a remittance, an EFTPOS payment, Xero in file mode, training terminal and NHI simulator.

## 0.19.1 – 2026-11-16 – **Monitor feed checked against the GE CARESCAPE Gateway Technical Manual (software 2.2)**
- **GE's own message form accepted** as well as IHE PCD-01: the parameter names in the manual's Appendix E (HR, SPO2-%, SPO2-R, NBP-S/D/M, AR1–8 and ABP1–8 arterial pressures, CO2-EX, CO2-RR, TP1-1/TP1-2) and GE's units ("mm (hg)", "cel"). A second SpO2 probe is not taken. End-tidal CO2 sent as a **percentage** is converted to mmHg using the barometric pressure in the same message (760 mmHg if none).
- **Readings the gateway back-collects** (up to 8 hours held by a monitor while it was offline) are now kept, and filed to whichever patient was connected at the time of each reading – never to the patient connected now. Before, the live feed dropped anything older than the last reading. Values the gateway sends again are kept once.
- **End of daylight saving:** the gateway repeats wall-clock timestamps in the 02:00 hour. On the live feed a timestamp with no offset in that hour is now placed by when it arrived, so the second 02:xx is not filed an hour early (and dropped). Files imported later keep the first occurrence.
- A caret in the gateway's HIS mapping (it arrives doubled, UNIT^^BED) still matches the monitor.
- Checked, no change needed: the gateway connects to BrightPAS as the TCP client (BrightPAS listens on the monitor interface); collection intervals on the gateway are 1–60 minutes, so the 5/15-minute chart intervals work with a 1- or 5-minute gateway setting.
- **Olympus CV-1500:** Olympus's own sales sheet lists still pictures as TIFF (standard) or JPEG (low quality) to portable memory, an image filing system or a server, SDI video outputs and remote control of a recorder – it does not mention DICOM. BrightPAS already takes both routes (DICOM node, and TIFF/JPEG from USB or a watched folder), so nothing changes until Olympus confirms which the tower uses.
- **SaferSleep:** no public interface specification – the record profile stays BrightPAS's own until SaferSleep supply theirs.

## 0.17.0 – 2026-11-14 – **Devices & SaferSleep: bedside monitor feeds with nurse validation, and the anaesthetic record interface (foundations)**
- **Devices & SaferSleep module (ADR 0029, spec 6 and 7.6):** built on the messaging engine, so allowed-IP lists, the message store and the message viewer apply.
  - **Bedside monitors (GE CARESCAPE B450 / B1x5 through the CARESCAPE Gateway):** vital signs arrive as HL7 ORU (IEEE 11073 codes; plain labels accepted) – heart rate, pulse, SpO2, NIBP, arterial pressure, respiratory rate, temperature, end-tidal CO2. Units are normalised, impossible values are discarded as artefact, and readings are kept at most every 30 seconds. A monitor BrightPAS does not know is **refused**, so a gateway set-up fault is seen.
  - **Connecting a patient:** on the clinical record's new **Monitor & anaesthesia** tab a nurse chooses the monitor at the bedside, sees its live values, and connects. One patient per monitor and one monitor per patient – enforced by the database. Moving from theatre to recovery swaps the monitor in one step. A monitor that is admitted to a different NHI cannot be connected. Monitors disconnect by themselves at discharge. Optional automatic connection when the monitor sends the NHI of an admitted patient.
  - **Nothing is charted until a nurse validates it:** every 5 minutes in theatre and recovery (15 on the ward; settings) a reading is offered. The nurse ticks the values to accept, adds consciousness, pain, oxygen and sedation, and presses **Validate and chart** – it becomes a normal observation marked *Device* with the early warning score – or **Don't chart** with a reason (artefact, probe off). Trend chart of the monitor values on the episode.
  - **SaferSleep out:** the admitted patient and booking are sent as ADT (A01 on admission or on entering theatre, A08 on request, A03 on discharge) with NHI, name, date of birth, location, surgeon, anaesthetist, planned procedure and recorded allergies. When no allergy is recorded nothing is said about allergies.
  - **SaferSleep in:** the completed anaesthetic record (drugs, infusions, events, vital signs and the PDF) is matched by the visit number BrightPAS sent (else NHI and a single admission that day) and filed: PDF in the patient's documents, a signed anaesthetic note, and the drugs in the medicines list marked *SaferSleep*. A **correction** replaces the earlier filing; a resent message is not filed twice; a record whose NHI does not fit the visit is **refused**; anything unmatched waits under **Monitors & SaferSleep › SaferSleep** to be filed by hand (only that patient's episodes are offered).
  - **Monitors & SaferSleep** page: monitors with live status (online/offline, connected patient, NHI mismatch warning), interfaces, anaesthetic records, settings. Module set-up wizard, patient merge, standards self-test, reporting views vDeviceCapture and vAnaestheticDrug, demonstration monitors and records. New permissions: devices.use (Nurse, Anaesthetist), devices.manage (System Administrator).
  - **Not included, on purpose:** waveforms and alarms. BrightPAS is a record; the monitor and central station remain the alarm system.
- The HL7 layouts are BrightPAS interface profiles built from the standards. **Before go-live** capture real messages from TDS's CARESCAPE Gateway and agree the record layout with SaferSleep (mapping changes only).
- Release build now **fails if any dependency has a known vulnerability** (NuGet and npm audit).
- **Hardening and review (before release):**
  - **.NET code analysis is part of the build:** recommended rules plus every security and reliability rule; any finding fails the build. Rules turned off on purpose are listed with the reason in `.editorconfig`. All findings were fixed: culture-safe string comparisons, the security self-test's deliberate old-TLS probe scoped and documented, a certificate leak in the self-test fixed.
  - **Every process runs in New Zealand English** (web, Setup, test robot, licence tools), so the server's regional settings cannot change number or date formats in HL7, CSV or JSON.
  - **Listeners that file clinical data now fail closed:** an MLLP interface that hands messages to a module (lab results, monitors, SaferSleep) must list the systems allowed to connect, and with no list it refuses everyone (previously anyone could connect). The old Labs:Mllp listener does the same. A lab interface created from settings at upgrade with no allowed address is created switched off.
