# Changelog

## 0.16.0 – 2026-11-14 – **BrightPAS Scribe: AI dictation and ambient documentation (foundations)**
- **BrightPAS Scribe module (ADR 0028, spec 7.22 / 7.17):** everything the scribe writes is a **draft** until the clinician checks and signs it.
  - **Ambient scribe:** Start scribe from the clinical record (or Scribe › new session) → **patient consent** (this visit, or standing and withdrawable; product named) → record from a headset/desk microphone (encrypted, saved every few seconds) → **transcribe** → **draft** from a TDS template → **review screen** with the draft beside the transcript (hover a sentence to see where it came from; set speakers) and **safety checks** (doses, "units", trailing zeros, look-alike/sound-alike medicines, laterality, words the engine was unsure of) → confirm and **sign**. The signed note is filed as a PDF in the patient's documents and, with a booking, as a signed note in the clinical record marked **AI-assisted** with the engines and % edited. Audio is deleted on signing (or after a retention period).
  - **Dictation:** a Dictate button on note fields (clinical record notes, endoscopy conclusion/recommendations/patient advice) – voice commands ("new paragraph", "full stop", "comma", "scratch that", "next field"), TDS dictionary and NZ spelling, with the same safety warnings.
  - **NZ language:** NZ/AU spelling corrections (anaesthetic, oesophagus, haemorrhage …), te reo Māori kupu and place names with macrons, and a **TDS custom dictionary** (clinicians, medicines, procedures, places; "sounds like" corrections) – clinician names added automatically on the demo system.
  - **Engines (spec 7.22.3):** speech = Off, on site (any OpenAI-compatible transcription server, e.g. Whisper) or cloud; drafting = **template only (no AI)**, on-site language model (OpenAI-compatible chat) or **Claude API with a de-identified transcript** (names, NHI, MRN, date of birth, phone, address replaced by tokens and put back only inside BrightPAS). Cloud processing needs the privacy assessment reference recorded.
  - **Templates** (consultation, pre-anaesthetic, triage call, pre-admission call, discharge summary, GP letter, patient instructions, post-op review) with versioning and **clinical governance approval** (not by the author); unapproved templates cannot be used.
  - **Medow Health option (spec 7.17):** switch on only after the PIA addendum, HISF supplier assessment and data processing agreement are recorded; sends only minimum data (first name, age, sex, procedure, alert types); drafts return by a **bearer-token API** (/api/scribe/inbound) or paste, as unsigned drafts marked Medow Health.
  - **Accuracy audit:** % of the draft changed before signing, per clinician and engine; every session, consent, draft and signature audit-logged; reporting view vScribeSession.
  - Module set-up wizard, patient merge, standards self-test, demonstration sessions. New permissions: scribe.use (Nurse, Anaesthetist, Surgeon / Endoscopist), scribe.approve (Surgeon / Endoscopist), scribe.manage (System Administrator). The browser may use the microphone on BrightPAS pages.
- Test robot: **virtual speech server and language model** – ambient session through the screens with the browser's virtual microphone (consent, record, transcribe, draft, safety checks, sign), cloud drafting checked for de-identification, dictation with NZ spelling/te reo/voice commands, Medow draft with token (wrong token refused).

## 0.15.1 – 2026-11-14 – **Endoscopy: NBSP extract, report to GP by HealthLink, drawing on pictures, 4K/MP4 capture, TIFF**
- **Bowel screening (NBSP):** Endoscopy › Bowel screening tab lists screening colonoscopies with the programme dataset (caecal intubation, BBPS, withdrawal, polyps seen/removed/retrieved, largest polyp, adenomas and advanced adenomas, serrated lesions, cancer suspected/confirmed, tattoos, complications, surveillance) and what is missing for each (NBSP number, signing, histology). **Download NBSP extract** gives an encrypted CSV (field layout to confirm with the National Screening Unit); exported procedures are marked.
- **Report to the GP by HealthLink:** a signed report can be sent with one click – a final covering letter (conclusion, recommendations, follow-up, histology to follow) with the **report PDF with pictures embedded in the HL7 REF^I12 (OBX ED)**; shown on the report with the letter number and HealthLink acknowledgement. Amending a report allows a corrected one to be sent. Letters gain PDF attachments (letters.LetterAttachments).
- **Drawing on pictures:** Draw on picture – arrow, circle, pen and text labels in five colours with undo; saved as an annotated copy linked to the original (never changed), which takes the original's place in the reports.
- **Capture quality:** choose 720p, 1080p or **4K**; the screen shows what the capture device is actually sending; recordings prefer **MP4 (H.264)** (WebM where the browser cannot) at 4/8/25 Mbit/s by resolution. Works with any capture device Windows shows as a camera (USB 4K boxes, internal cards, pass-through between tower and screen).
- **TIFF pictures:** TIFF uploads (and TIFF from capture boxes) are converted to PNG for viewing and reports; the original TIFF is kept and can be downloaded. Baseline 8-bit greyscale/RGB, uncompressed, LZW or PackBits.
- Messaging folder writer no longer fails when a file with the same name is still waiting in the folder (adds a suffix).
- Test robot: TIFF upload, drawing an arrow, endoscopy report to GP by virtual HealthLink (PDF inside the message), NBSP extract.

  - **Capture screen** for towers without DICOM: the capture card shows as a camera in the browser – live video, **Take picture** (Space / foot pedal), **Start/stop recording** (R) with video saved in chunks as it records; upload pictures or video from a file.
  - **Structured record (minimum standard terminology):** indications (incl. NBSP positive FIT), consent, sedation (medicines shown from the clinical record), scopes and tower (scope use recorded against the patient in Assets & CSSD; a scope that is not ready is refused), CO₂/water/ScopeGuide; gastroscopy extent, retroflexion, times and photo-documentation; colonoscopy extent, caecal landmarks, **Boston Bowel Preparation Scale**, withdrawal time (live timer), rectal retroflexion, reason if incomplete; modified Gloucester comfort.

  - **Sign** with hard stops for the minimum dataset (extent, times, landmarks, BBPS, comfort, specimen pots, conclusion); **amend** with a reason; **histology** added after signing.
  - **Reports with pictures:** clinical report (for the record, GP and referrer) and a plain-language **patient report** (what we found, pictures, polyp/biopsy/tattoo advice, sedation and when to get help – wording editable in Settings); protected PDF download or saved to the patient's documents.
  - **Quality indicators** per endoscopist: caecal intubation, adenoma and serrated detection, polyp detection and retrieval, withdrawal time, adequate prep, discomfort, rectal retroflexion, complications; gastroscopy D2, retroflexion, ≥ 7 min, photo-documentation; targets set by TDS.   - Video retention setting; module set-up wizard; patient merge; standards self-test; reporting views vEndoscopyProcedure, vEndoscopyPolyp; demonstration data (12 procedures with findings, polyps, histology, tattoos, biopsies and invented pictures).
  - New permissions: endoscopy.view, endoscopy.write (Nurse, Surgeon / Endoscopist), endoscopy.sign (Surgeon / Endoscopist), endoscopy.manage (System Administrator).

## 0.14.0 – 2026-11-14 – **Clinical record (eMR): admission, safety checklist, theatre record, observations, medicines, discharge**

  - **Counts and specimens:** initial/additional/closing/final counts with second checker; discrepancies must be resolved; numbered specimens collected → sent → received by the lab.

  - **Medicines and fluids:** medicines given (barcode optional), **controlled drug register** with witnessed entries and running balance, fluid balance, blood products (two checkers, cold chain, reactions).
  - **Notes:** nursing, medical, operation, anaesthetic, discharge and patient-instruction notes from templates; draft or signed; amendments keep the original.
  - **Discharge:** criteria confirmed; escort home and overnight carer required after sedation/anaesthesia (or a recorded override); doctor review needed when the last EWS is above 2; Sign Out must be complete; emergency transfer to hospital recorded.
  - Patient merge, module set-up wizard, standards self-test, reporting views (vEpisode, vControlledDrugRegister), demonstration data (controlled drugs, six completed records, today's admitted patients).

## 0.13.0 – 2026-11-14 – **Assets & CSSD: equipment, sterile traceability, endoscopes, stock and purchasing**

Tray labels to the Zebra printer. **Recall by load** quarantines stock and lists every patient/case; tracing by tray or patient.
  - **Endoscopes:** leak test, manual clean, AER cycle, drying cabinet, use on a patient, microbiology and repairs; "Ready" only after leak test and AER since last use and within the storage time (72 h default); failures quarantine and raise a nonconformance.

  - **Nonconformance / CAPA:** raised automatically or by hand; root cause and corrective action needed to close.
  - **Stock and implants:** lots and expiry, first-expiry-first-out use, stocktake adjustments, **implant records against the patient** (lot, serial, site) with recall by product and lot.
  - **Purchasing:** reorder alerts create draft orders per supplier; approval (purchasing.approve); goods receipt with lot/expiry; supplier invoices matched to goods received ($1 / 1 %); **Xero bills CSV** export.
  - Patient record panel "Sterile items, scopes & implants"; module set-up wizard; demonstration data (machines, six scopes, GE CARESCAPE monitors, Olympus tower, trays with contents, loads, a load waiting for release, a quarantined scope, a locked-out warmer, stock, an order, an invoice and an implant); reporting views vTrayTrace, vImplant, vMaintenanceDue; self-test suite; test-robot scenario "Virtual washer (Belimed log)".

## 0.12.0 – 2026-11-10 – **Messaging & integration engine (TDS's own Rhapsody/MuleSoft-style engine)**
- **Messaging & integration engine module (ADR 0021):** one encrypted message store for every message in and out, with readable views, step history, search (interface, NHI, reference, date), replay/resend with a reason (audited), queues with automatic retry (1 min → 4 h back-off) and a "gave up" list, a live dashboard per interface (running, volumes, waiting, failed), and alerts (failures in a row, gave up, quiet for N hours, listener stopped) shown on screen and emailed to the support contact (no patient details).
- **Connections (communication points), all set up in the app:** HL7 over MLLP (listen with IP allow-list / send with ACK), **DICOM node** (C-STORE and C-ECHO for devices registered by IP + AE title; optional archive of the original files), **REST API in** (`/api/integration/in/{code}` with a per-interface key) and **REST/FHIR out**, folders (watch / write), and the **SQL connector** (read another database with a SELECT and watermark; write with a parameterised INSERT/UPDATE/EXEC – single statements only, values only ever as @parameters, connection strings encrypted). Test-connection button and "send a test message" simulator on every interface.
- **Formats:** HL7 v2, FHIR/JSON, **DICOM** (header as the DICOM JSON model; DICOM files in and out), **CDA/XML**, **X12 EDI**, text. Messages are matched to patients by NHI.
- **Visual flow designer (like Rhapsody routes / MuleSoft flows):** drag inputs, filters, Yes/No decisions, mappers and outputs onto a canvas and wire them; checks catch loops, missing connections and format mismatches. **Test harness** runs the flow as drawn (even unsaved, optionally with draft mappings) against a pasted sample or a DICOM file and shows the path taken and the output at every step – nothing is stored or sent.
- **Mapping designer:** input and output shown as readable trees (HL7 "PID-5 Patient name", DICOM "(0010,0010) PatientName"); drag a field onto a rule; functions (copy, fixed value, translate, date format, join, split, part, case, default, clear) with optional conditions and repeating segments (OBX[*]); live output preview with validation. Versions: draft → sent for approval → **approved by a second person** → live; instant rollback to an earlier version. **Translation tables** with CSV import/export.
- **AI troubleshooting assistant (off by default):** every message has a built-in "Why?" explanation that never leaves BrightPAS. Administrators can switch on an AI assistant (Claude API by default) only after recording the privacy assessment reference; it receives a **de-identified summary** only (message shape without values, redacted errors, flow and mapping rules), which is shown before sending and recorded in the audit log.
- **MCP server for AI tools** (`/api/mcp`): read-only engine status, failed messages with redacted errors, flows and explanations; never message content or patient identifiers; per-tool bearer tokens (hashed, expiring, revocable); every call audited.
- Lab results (MLLP), HealthLink letters, SMS and email now show on the same dashboard; the lab MLLP port from appsettings becomes the **labs-in** interface automatically.
- New role permission **messaging.view**; the Integration Administrator role manages the engine. DICOM library fo-dicom 5.2.6 (MS-PL). Database script 14-messaging.sql; the reporting script is now 90-reporting.sql (runs last).
- Tests: 289 + browser walk-throughs (interface editor, drag-and-drop mapping, second-person approval, flow drawn on the canvas, DICOM → HL7 ORM through the REST interface to a folder, MCP, real DICOM C-ECHO/C-STORE).

## 0.9.1 – 2026-11-08 – Always open the secure page
- Typing `BRIGHTPAS-SRV` or `http://BRIGHTPAS-SRV` now lands on `https://BRIGHTPAS-SRV` instead of "can't reach this page". Setup binds port 80 to the BrightPAS site, but BrightPAS answers plain HTTP **only** with a permanent redirect to https:// (GET/HEAD) and refuses everything else (HTTP 403 "https_required") – no page, sign-in or patient data ever travels unencrypted. - Self-test: "Unencrypted HTTP disabled" now checks that http:// redirects to https:// and that a sign-in sent over plain HTTP is refused.

## 0.5.6 – 2026-11-07 – Installer fix (folder permissions)
- **Fixed:** step 10 "Access to the path … Microsoft.Identity.Client.dll is denied" was a permissions fault, not a locked file (no worker process was running). The folder lock-down in 0.5.0–0.5.5 applied its rule to every existing file with `/T`, leaving those files without an Administrators entry – Setup (and diagnostics) could not even read web.config or older logs.
- Step 10 now first **repairs** both folders (take ownership for Administrators, reset all files to inherit, clear read-only), then copies files. If a file is still blocked it stops the IIS services (W3SVC, WAS), ends worker processes, retries, and starts IIS again.
- Folder lock-down rewritten: permissions are set once on each top folder and everything below inherits; icacls output is logged and failures stop Setup; a final check proves Administrators can write/read and the app pool account is present.
